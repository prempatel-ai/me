My Agent Keeps a Notebook

Nov 17, 2026 · 6 min read

Q-Learning is the center of Unit 2, so it gets its own post. I’ll explain it the way I’d explain it to a friend in college.

The notebook

Imagine you’re new in a college canteen. You don’t know what’s good, so you carry a small notebook. For every counter, you write how good each dish is. On day one the notebook is empty. After a few weeks it’s full of notes, and you stop guessing.

A Q-Learning agent does exactly this. The notebook is called the Q-table. Each row is a situation the agent can be in, which we call a state. Each column is something it can do, an action. The number in each cell says how good that action is in that state. The Q comes from “quality”. At the start every number is 0, so the notebook is useless.

One thing I had to separate in my head was reward and value. Reward is what you get right after you do something, like the dish tasting good today. Value is how good you expect things to be from here on, if you keep going.

And this is the part I like. If the notebook is right, you don’t need anything else. In any situation, you look at that row and pick the biggest number. That’s the policy. A good table gives you a good policy for free.

How the agent fills it in

It’s four steps, repeated again and again.

  1. Start with a blank notebook, all zeros.
  2. Choose what to do.
  3. Do it, and see what happens.
  4. Fix the note.

Choosing what to do

The agent uses a number called epsilon, between 0 and 1. It’s the chance of doing something random. It starts at 1.0, so at first everything is random, and that’s fine because the notebook knows nothing yet. Then epsilon slowly goes down and the agent trusts its notes more.

It’s the same as the canteen. In the first weeks you try random dishes. After a few months you mostly order your favourites, and sometimes you still try something new.

Fixing the note

After the move, the agent sees the reward and the new state. Now it fixes the note for the thing it just did.

Q(St, At) ← Q(St, At) + α [ Rt+1 + γ maxa Q(St+1, a) − Q(St, At) ]

It looks scary, so here it is in words. New note = old note + a small step toward (what I got − what I thought). The old note is what I thought. What I got is the reward, plus the best note available in the next state, shrunk a bit by gamma. That second part has a name, the TD target. If what I got matches what I thought, nothing changes. If not, the number moves a little. How big the step is depends on the learning rate, alpha.

One detail matters. To find the best note in the next state, the agent just takes the highest number there. No randomness in that part. After that it moves to the new state and the loop starts again.

Act one way, learn another

This is what off-policy means, and it makes sense once you see it. When the agent acts, it uses epsilon, so sometimes it’s random. When it updates, it takes the best next note, as if it will always act perfectly.

In the canteen, you order a random dish today because you’re exploring. But when you write the note, you assume that next time you’ll order the best dish there. You act one way and you learn as if you’ll act another way.

On-policy is when the same policy is used for both. The example is Sarsa, where the next move that goes into the update is chosen with epsilon too, so there’s no max in it.

Quick recap

  • Q-Learning keeps a table of notes, one number for every state and action.
  • It starts at 0, and an optimal table gives an optimal policy.
  • Each step: choose with epsilon, act, then fix the note using the TD target.
  • The TD target uses the best next note, so acting and learning use different policies. That’s off-policy.
