How an Agent Learns From a Table

Nov 16, 2026 · 8 min read

So I finished Unit 2 of the course. This one is about Q-Learning. In Unit 1 I used a library to train the lunar lander. This time there is no library. I wrote the algorithm myself in plain Python.

Here is everything from the unit, in simple words, the way I understood it.

What’s in this unit

Four things, basically, and then the coding part:

  • Value-based methods
  • The Bellman equation
  • Monte Carlo vs Temporal Difference
  • Q-Learning itself
  • Coding it on two small games, FrozenLake and Taxi

Value-based methods

In Unit 1 we saw two ways to get a good policy. One is to train the policy directly. The other one is value-based, and that’s what this unit is about.

In value-based methods, you don’t train a policy at all. You train something that tells you how good each situation is. Then the agent just picks the option with the best value. That simple rule is called the greedy policy.

There are two types of values.

  • State value, V: how good is it to be in this state.
  • Action value, Q: how good is it to take this action in this state.

Think of a crossing in a city. V tells you how good the crossing is. Q tells you how good each road from that crossing is. We mostly use Q, because the agent has to choose an action.

The Bellman equation

Here’s the problem. To know the value of a state, you have to add up all the rewards you will get from there until the end of the game. Doing that for every single state is a lot of work.

The Bellman equation makes it easy. The value of a state is the reward you get now, plus the value of the next state (multiplied by gamma). That’s it. You don’t go to the end of the game, you just look one step ahead.

V(s) = R + γ V(s′)

The course asked what happens if gamma is 0, 1, or very big. This is what I think. If it’s 0, the agent only cares about the reward right now. If it’s 1, the agent cares about the future as much as now. If it’s very big, the future matters more than now, and the numbers go crazy.

Monte Carlo vs Temporal Difference

Both are ways to learn from experience. The only difference is when you learn.

Monte Carlo: play the whole game first, then learn from the total reward at the end.

Temporal Difference (TD): learn after every step. But you don’t know the total reward yet, so you guess it. The guess is the reward you just got plus the value of the next state.

The course uses a mouse looking for cheese, with learning rate 0.1. With Monte Carlo, the game ends, the total reward is 3, and the value goes from 0 to 0.3. With TD, the mouse takes one step, finds a cheese (reward 1), and the value goes from 0 to 0.1 right away.

Using a guess to make another guess is called bootstrapping. It sounds weird, but it works. And Q-Learning uses TD.

Q-Learning

So what is Q-Learning? It’s a table. Rows are states and columns are actions. Each box has a Q-value, which says how good that action is in that state. At the start every box is 0. The agent plays and keeps updating the boxes. At the end, for each state you pick the action with the biggest number, and that is your policy.

There are four steps.

  1. Make the Q-table, all zeros.
  2. Pick an action using epsilon-greedy.
  3. Do the action and see the reward and the new state.
  4. Update the Q-value.

Epsilon-greedy is simple. Epsilon is the chance of doing a random action. It starts at 1.0, so at first everything is random (exploring). Then we slowly lower it, so the agent starts using what it learned (exploiting). It’s the same exploration vs exploitation thing from my Unit 1 blog, but now it’s just a number.

The update formula looks scary, but it isn’t.

Q(s, a) ← Q(s, a) + α [ r + γ maxa′ Q(s′, a′) − Q(s, a) ]

In words: new value = old value + learning rate × (what I got − what I thought). What I got is the reward plus gamma times the best Q-value of the next state. If what I got is the same as what I thought, nothing changes. If not, the value moves a little.

One more thing, off-policy. When the agent picks an action, it uses epsilon-greedy. But when it updates, it uses the best next action (the max). So two different policies are used, and that’s why it’s called off-policy. Sarsa is the on-policy one.

A small example by hand

The course has a small maze. Learning rate is 0.1, gamma is 0.99. Small cheese is +1, big cheese is +10, poison is -10. The table starts at all zeros.

Step 1: the mouse moves right randomly and finds a small cheese, reward 1. Q = 0 + 0.1 × (1 + 0.99 × 0 − 0) = 0.1.

Step 2: the mouse moves down randomly and eats the poison, reward -10. Q = 0 + 0.1 × (-10 + 0.99 × 0 − 0) = -1.

Just two steps and the table already knows that going down there is bad. The rest is just repeating this many times.

Coding it: FrozenLake

FrozenLake is a 4x4 grid. S is the start, G is the goal, F is frozen ice you can walk on, and H is a hole. There are 16 states and 4 actions. The reward is +1 only when you reach the goal, otherwise 0. I started with the non-slippery version, where the agent always goes in the direction you choose.

First the environment and the Q-table:

env = gym.make("FrozenLake-v1", map_name="4x4", is_slippery=False)
Qtable = np.zeros((env.observation_space.n, env.action_space.n))

Then epsilon-greedy:

def epsilon_greedy_policy(Qtable, state, epsilon):
    if random.uniform(0, 1) > epsilon:
        return np.argmax(Qtable[state])
    return env.action_space.sample()

And the update, which is the whole algorithm:

Qtable[state][action] += learning_rate * (
    reward + gamma * np.max(Qtable[new_state]) - Qtable[state][action]
)

The settings I used: 10000 episodes, learning rate 0.7, gamma 0.95, and epsilon going from 1.0 down to 0.05. The decay rate is the important one. The only reward is at the goal, so if epsilon drops too fast, the agent stops exploring before it finds the goal. Then every box stays 0 and it learns nothing.

Taxi

Taxi is harder. A taxi has to pick up a passenger and drop them at the right place. It has 500 states and 6 actions, including pickup and drop off.

The rewards are interesting. Every step is -1, delivering the passenger is +20, and a wrong pickup or drop off is -10. Nobody tells the taxi to be fast. The -1 on every step does that.

The same code worked here. I only made a 500 x 6 table and trained for 25000 episodes. To pass the hands-on, your score (mean reward minus standard deviation) must be 4.5 or more. [ADD: your Taxi score]

What’s next

A Q-table works for 16 or 500 states. But for a game like Doom there are millions of states, and a table can’t handle that. So in Unit 3 a neural network will replace the table. That’s the “deep” part from my first post.

Final thoughts

Before this unit, words like policy, value and exploration were just words for me. Now I’ve seen them in code. The policy is just picking the biggest number in a row, exploration is a random number compared with epsilon, and learning is one line that moves a number a little.
