Coding Q-Learning From Scratch: FrozenLake and Taxi

Nov 19, 2026 · 10 min read

This is the hands-on part of Unit 2. In my last post I did Q-Learning by hand with a mouse in a maze. Now we actually code it.

No library does the learning here. It’s only Python, NumPy and Gymnasium. We train one agent on FrozenLake, then a harder one on Taxi, and push both to the Hugging Face Hub.

Before you start

The course recommends Google Colab for this, and that makes sense, because you don’t have to set up anything on your own computer. Open the notebook from the course page and run it cell by cell.

To pass the hands-on for the certificate, you need to push your Taxi model to the Hub and get a result of 4.5 or more. The result is mean reward minus the standard deviation of the reward. You can see it on the leaderboard.

Setup

First you install the libraries. Gymnasium has the two games, pygame draws them, and NumPy holds the Q-table.

Then there is a virtual display. We need it because at the end we record a replay video of the agent, and Colab has no real screen. After this step, the notebook kills the runtime on purpose with os.kill(os.getpid(), 9). It looks scary but it’s normal. It just restarts so the new libraries get used. Connect again and run from the virtual display cell.

Then the imports. random is for the epsilon dice, imageio is for the video, tqdm is the progress bar, and pickle is for saving the model.

Part 1: FrozenLake

The agent has to walk from the start tile S to the goal tile G, only on frozen tiles F, and avoid holes H. It’s a 4x4 map here, but there is an 8x8 one too. You can also make your own map with the desc parameter.

There are two modes. With is_slippery=False the agent always goes where you tell it (deterministic). With is_slippery=True it can slide in another direction (stochastic). We start with non-slippery.

env = gym.make("FrozenLake-v1", map_name="4x4", is_slippery=False, render_mode="rgb_array")

The render_mode="rgb_array" part is there for the video at the end.

The course says to always check the environment first, so let’s do that.

  • Observation space: Discrete(16). The state is just one number, calculated as row * ncols + col. So the goal is 3 * 4 + 3 = 15.
  • Action space: 4 actions. 0 is left, 1 is down, 2 is right, 3 is up.
  • Rewards: +1 for reaching the goal, and 0 for everything else, even holes.

The Q-table

Step 1 of the algorithm is making the table. We don’t type 16 and 4 by hand. We ask the environment, so the same code works for other games.

state_space = env.observation_space.n
action_space = env.action_space.n

def initialize_q_table(state_space, action_space):
    return np.zeros((state_space, action_space))

Qtable_frozenlake = initialize_q_table(state_space, action_space)

The two policies

Q-Learning is off-policy, so we need two policies. One for acting and one for updating.

The greedy policy takes the action with the highest value in that row. This is also the final policy we get after training.

def greedy_policy(Qtable, state):
    return np.argmax(Qtable[state][:])

The epsilon-greedy policy is for training. It rolls a random number. If the number is bigger than epsilon, it takes the greedy action. If not, it takes a random action.

def epsilon_greedy_policy(Qtable, state, epsilon):
    random_num = random.uniform(0, 1)
    if random_num > epsilon:
        action = greedy_policy(Qtable, state)
    else:
        action = env.action_space.sample()
    return action

The course says the exploration settings are the most important ones. If epsilon goes down too fast (decay_rate too high), the agent doesn’t explore enough and can get stuck.

The training loop

In simple words, the loop does this:

  1. For each episode, lower epsilon a little and reset the game.
  2. For each step, pick an action with epsilon-greedy.
  3. Do the action, and see the new state and the reward.
  4. Update the Q-value.
  5. If the game is over, stop. If not, the new state becomes the current state.
def train(n_training_episodes, min_epsilon, max_epsilon, decay_rate, env, max_steps, Qtable):
    for episode in tqdm(range(n_training_episodes)):
        epsilon = min_epsilon + (max_epsilon - min_epsilon) * np.exp(-decay_rate * episode)
        state, info = env.reset()

        for step in range(max_steps):
            action = epsilon_greedy_policy(Qtable, state, epsilon)
            new_state, reward, terminated, truncated, info = env.step(action)

            Qtable[state][action] = Qtable[state][action] + learning_rate * (
                reward + gamma * np.max(Qtable[new_state]) - Qtable[state][action]
            )

            if terminated or truncated:
                break
            state = new_state
    return Qtable

The epsilon line makes it go down smoothly with an exponential decay. The Qtable line is the update formula from my first Q-Learning post.

Then we train:

Qtable_frozenlake = train(n_training_episodes, min_epsilon, max_epsilon, decay_rate, env, max_steps, Qtable_frozenlake)

After this, you can print the Q-table and look at it. It’s no longer all zeros.

Testing the agent

For evaluation, the agent plays 100 games using only the greedy policy, no random moves. We get the mean reward and the standard deviation.

def evaluate_agent(env, max_steps, n_eval_episodes, Q, seed):
    episode_rewards = []
    for episode in tqdm(range(n_eval_episodes)):
        if seed:
            state, info = env.reset(seed=seed[episode])
        else:
            state, info = env.reset()
        total_rewards_ep = 0

        for step in range(max_steps):
            action = greedy_policy(Q, state)
            state, reward, terminated, truncated, info = env.step(action)
            total_rewards_ep += reward
            if terminated or truncated:
                break
        episode_rewards.append(total_rewards_ep)
    return np.mean(episode_rewards), np.std(episode_rewards)

Pushing to the Hub

One function does all of this. push_to_hub tests the agent, makes a model card, records a replay video, and uploads everything to the Hub. The model is saved as q-learning.pkl.

You need three things first:

  1. A Hugging Face account.
  2. A token with the write role. Make it in your settings, then run notebook_login() and paste it.
  3. A model dictionary with the hyperparameters and the Q-table in it.
model = {
    "env_id": env_id,
    "max_steps": max_steps,
    "n_training_episodes": n_training_episodes,
    "n_eval_episodes": n_eval_episodes,
    "eval_seed": eval_seed,
    "learning_rate": learning_rate,
    "gamma": gamma,
    "max_epsilon": max_epsilon,
    "min_epsilon": min_epsilon,
    "decay_rate": decay_rate,
    "qtable": Qtable_frozenlake,
}

username = "your-hf-username"
repo_name = "q-FrozenLake-v1-4x4-noSlippery"
push_to_hub(repo_id=f"{username}/{repo_name}", model=model, env=env)

Part 2: Taxi

Taxi is harder. There are four spots on the grid: Red, Green, Yellow and Blue. The taxi starts at a random square and the passenger is at a random spot. The taxi has to go to the passenger, pick them up, drive to the destination (another one of the four spots), and drop them off. Then the game ends.

env = gym.make("Taxi-v3", render_mode="rgb_array")
  • States: 500. That’s 25 taxi positions, times 5 passenger locations (including inside the taxi), times 4 destinations.
  • Actions: 6. South, north, east, west, pickup, drop off.
  • Rewards: -1 for every step, +20 for delivering the passenger, and -10 for a pickup or drop off at the wrong place.

The Q-table is now 500 x 6, and we make it with the same function:

Qtable_taxi = initialize_q_table(state_space, action_space)

The hyperparameters change a bit. We train for 25000 episodes, and the decay rate is 0.005 instead of 0.0005. The learning rate (0.7), gamma (0.95), max_steps and the epsilon range stay the same.

There is also a long eval_seed list. Do not change it. It makes sure every classmate’s agent is tested from the same taxi starting positions, so the leaderboard is fair.

Then we train with the same function and push the model, using a new repo name:

Qtable_taxi = train(n_training_episodes, min_epsilon, max_epsilon, decay_rate, env, max_steps, Qtable_taxi)

The model dictionary is made the same way, but with Qtable_taxi. Then check the leaderboard for your result. [ADD: your Taxi result and Hub link]

Part 3: Loading a model from the Hub

This part is cool. Anyone can share a Q-Learning model on the Hub, and you can load it in a few lines. You go to the list of q-learning models on the Hub, copy a repo id, and use load_from_hub with that repo id and the file name q-learning.pkl.

model = load_from_hub(repo_id="ThomasSimonini/q-Taxi-v3", filename="q-learning.pkl")
env = gym.make(model["env_id"])
evaluate_agent(env, model["max_steps"], model["n_eval_episodes"], model["qtable"], model["eval_seed"])

That one is the course author’s Taxi model. You can try other people’s models the same way.

Extra challenges

The course ends with some things to try.

  • Train for more steps. The course says that with 1,000,000 steps they saw great results.
  • Try different hyperparameters, and look at what your classmates used.
  • Push your new model to the Hub and see where you land on the leaderboard.
  • Change the environment, for example the slippery FrozenLake.

What’s next

A Q-table is a good idea, but it doesn’t scale. For a game like Doom there are millions of states, and a table for that is not practical. That’s why Unit 3 is Deep Q-Learning, where a neural network guesses the Q-values for each action instead of a table.
